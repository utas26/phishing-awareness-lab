Wi-Fi Password Auditing

See why a weak example is found in a short candidate list, then compare it with a stronger example and test a simulated change.

This is a synthetic teaching verifier, not a WPA capture or cracking tool. Each candidate really is hashed and compared locally, using a deliberately simplified SHA-256 format. Discovery, timing, access points, and settings are simulated. The lab accepts no targets, files, or passwords from you, requests no device permissions, and saves no session data. Never test real wireless networks without explicit authorization.

What does this fixture verify?

The browser computes SHA-256 of WIFI-TEACHING-V1|SSID|challenge|candidate for each supplied candidate, then compares the full result with the stored verifier. Only an exact match recovers the classroom password. The public challenge changes the hash input; it is not a secret.

This format is intentionally not WPA2/WPA3, a packet capture, a real handshake, or a model of real attack speeds. Real Wi-Fi authentication uses different protocols and protections. The principle illustrated here is candidate verification against supplied evidence.

    What the evidence can tell you

    • A matching candidate demonstrates that the fixed example password is in that tested list.
    • “Not found” means this list did not recover that fixture’s password. It does not prove a network is secure or a password is uncrackable.
    • Changing a passphrase requires fresh evidence for the new password. Old evidence still corresponds to the old password; rotation does not rewrite an old capture.
    • Use long, unique Wi-Fi passphrases, current router firmware, and supported modern Wi-Fi security. This simplified exercise does not assess real WPA2 or WPA3 protection.
