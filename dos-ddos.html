Plain-English word guide
Request
A visitor asking a website to do something, such as open a page.
Server
The computer that does that work. Here, think of a shop worker.
DoS: denial of service
In this lesson, one source overloads the server so genuine visitors have trouble using it.
DDoS: distributed denial of service
Several sources overload the server together. “Distributed” means spread across sources.
Queue
The waiting room. Here it has space for 20 requests.
Defence
A rule that limits unwanted work or reserves room for genuine visitors. Real systems can misidentify people, so protection needs careful testing.

1. Configure the workload

Every tick adds 6 legitimate requests from 3 clients. Choose service capacity below; the queue holds 20 requests. Admission occurs before service, so a full queue can still drop a burst even with higher capacity. One run is 12 modeled ticks. A tick is one calculation step, not a real-world second. Advanced playback takes about 6 seconds; the beginner animation is slower.

The layered model assumes trusted clients can be identified. It admits at most 4 other requests per tick. Real classifiers make mistakes; this is not a production configuration.Source blocking assumes the dominant overload source is correctly identified; it removes only one of five distributed sources. Incorrect identification could block legitimate clients. More capacity has infrastructure costs and does not guarantee protection from larger attacks. What this model can and cannot show

This is a deterministic capacity/queue model, not a packet generator or benchmark. DoS and DDoS use the same total offered load; only the modeled source count changes. A per-source limiter can be less effective when load is distributed. Fixed request costs, known client classes, FIFO scheduling and a short observation window simplify real systems. Queued requests at the end are pending, not automatically failures. Pause freezes playback; Step one tick advances exactly one modeled tick without leaving a timer running. Source blocking identifies one fictional overload source, not a real IP. Higher capacity has a modeled resource-cost trade-off. Layered mitigation requires capacity planning, detection and legitimate-user trade-offs.
