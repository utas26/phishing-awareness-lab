About this model, teaching notes & sources
  • Local real-time simulation: the animation and counters run entirely on this device. They do not measure an actual server or send attack traffic. Moving shapes represent request bundles, not a literal packet count.
  • Simplified capacity model: genuine traffic is 30 requests/s; capacity is 120 requests/s. When demand exceeds capacity, processing is shared proportionally between genuine and attack requests. Genuine served rate = 30 × min(1, 120 ÷ total incoming rate). “Affected” means not served in that interval; in a real system those requests might be delayed, dropped, or time out. This model has no queue, protocol details, or per-client prioritization.
  • Equal total attack traffic: the slider sets the combined rate for either attack scene. DoS uses one source; DDoS divides that rate equally across six example sources. A DDoS attack is not necessarily more damaging than a single-source attack at the same effective load.
  • Blocking is an idealized example: “Block one source” assumes one source can be correctly identified and completely filtered before its traffic reaches the server. It removes all of this single-source DoS traffic, but only one sixth of this DDoS traffic. Real attacks can involve spoofing, reflection, changing sources, and upstream congestion, so this is not a universal defense.
  • Terminology: denial of service (DoS) is the broad category; DDoS is its distributed form. In this comparison, “DoS” means the single-source example. Traffic floods are one way to deny service; other attacks exploit vulnerabilities or exhaust particular resources. Botnets are common in DDoS attacks, but not required.
  • Controls: selecting a scene, adjusting the rate, or changing source blocking switches to manual mode. Restart resets the current scene and counters. Pausing also pauses automatic changes. Hidden browser tabs pause simulation time. Reduced-motion preferences start the simulator paused; Play remains available.
